# Checkpoint reference

This is the mapathon's answer key. Mapping in a real project has no single right answer, so each checkpoint is a state participants can see on their own screen. Use this page to check a participant's progress at a glance.

## Checkpoints by step

| Step | Checkpoint (what the participant should see) | How a helper checks | If it isn't there |
| --- | --- | --- | --- |
| Before you start | Their OSM username at the top right of the Tasking Manager | Look at the top right of tasks.hotosm.org | Not confirmed yet: find the email, check spam. Logged in to the wrong site: log in on tasks.hotosm.org itself. Struggling with shapes later: send them to iD's walkthrough |
| 1. Pick a square | The project number matches this month's, the task shows as locked for mapping by them, and iD shows the task outline | Tasking Manager tab: compare the project number with the whiteboard, and check the task panel names them | Wrong number: search for this month's number again. iD didn't open: click Map again and allow pop-ups for tasks.hotosm.org |
| 2. Trace in iD | The left panel names a feature type the project's instructions ask for (for buildings: a closed, squared outline) | Click one of their features and read the left panel; compare with the project's Instructions tab | Wrong kind of feature: check the project number first, then reread the instructions. Undo with Ctrl+Z; square a building with Q |
| 3. Save and submit | The Save button shows 0 unsaved edits, the comment includes the project hashtag and #AUmapathon, and the square changes color on the project map | Their latest changeset comment on their openstreetmap.org profile; the Tasking Manager project map | Upload failed: check Wi-Fi and click Upload again. Comment missing: add it on the next save. Still locked: open the task and submit it, or choose Stop mapping |

## What was and wasn't tested

These materials were written without live access to OpenStreetMap or the Tasking Manager. Button names and checkpoint wording follow the iD editor's documented shortcuts and the HOT Tasking Manager's published workflow, but none of the steps was clicked through while writing.

Test before the first public session, ideally at the staff pilot, and correct the cheat sheet, slides and website wherever the wording on screen differs:

- [ ] Setup: the exact sign-up and log-in button labels, where the username shows in the Tasking Manager, and the path to iD's walkthrough (Help, then Start the walkthrough).
- [ ] Step 1: where the project number shows, the wording when a task is locked, the Map button, and choosing iD Editor.
- [ ] Step 2: shortcuts 2, 3 and Q, and the Building and road presets in the left panel.
- [ ] Step 3: whether the Tasking Manager fills in the project hashtag, the Upload button label, that Save shows 0 after uploading, the "completely mapped" question, the Stop mapping button, and the square changing color.
- [ ] The live stats slide (slide 13): that ohsomeNow loads inside the slide on the room's screen and Wi-Fi, and that one practice edit with #AUmapathon shows up.
